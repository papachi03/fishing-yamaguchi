# 「現地の声」投稿機能 設計書（2026-09-20）

釣り人が現地の情報（投稿者名・場所・コメント・写真など）を投稿でき、すぐ公開される仕組み。
ダディと対話で決めた内容の記録。実装計画はこの文書を元に別途作る。

## 決定事項（ダディ承認済み）

| 論点 | 決定 |
|---|---|
| 投稿できる人 | 誰でも。承認なしで即公開 |
| 荒らし対策 | ロボット除け＋連続投稿制限＋通報ボタン（3件で自動非表示）＋管理者削除 |
| 場所の選び方 | ①具体的な釣り場（プルダウン）②〇〇市内（詳しい場所は非公開）③場所不明 |
| 釣り場リストの範囲 | 海況を出している5エリア（萩・長門・下関・下松・防府）の漁港・堤防・有名ポイント |
| 表示場所 | 新ページ「現地の声」（reports.html）＋SEAページの各エリアに最新2件 |
| 入力項目 | 名前・場所・コメント（必須）＋写真1枚・釣れた魚・いつの情報か・風の体感3択（任意） |
| 管理 | 専用の管理ページ＋合言葉。あわせてDiscord通知に削除リンク |

## 1. 全体の形

- **サイト側**：既存のViteサイトに `reports.html` と `src/js/pages/reports.js` を追加。SEAページ（`sea.js`）に各エリアの最新2件を差し込む。
- **受け皿**：新しいCloudflare Worker `yfj-reports`。置き場所は **workers.dev のアドレス**（`tproject-jp.com` の下には置かない）。
  - 理由：誰でも投稿できる場所は、荒らされるとドメインごとGoogleセーフブラウジングに判定される恐れがある。2026-09-13〜15に tproject-jp.com が `/ig/start` の件で判定を受け、Instagram連携まで止まった。看板ドメインと投稿の受け皿は分ける。
  - 将来、釣りサイトに独自ドメインを取ったらその下へ移せる。
- **保存**：投稿の本文はKV（1投稿1キー）、写真はR2（無料枠10GB）。写真はWorker経由で配信する。
- **費用**：0円（Workers無料枠・KV無料枠・R2無料枠・Turnstile無料）。
- Cloudflareのアカウントは Hoodhomies（Instagram連携のWorkerと同じ）。

## 2. 投稿の中身

| 項目 | 形式 | 必須 | 制限 |
|---|---|---|---|
| 投稿者名 | 自由入力 | ○ | 20文字。「ダディ」「管理者」「YFJ」「admin」等を含む名前は拒否 |
| 場所 | プルダウン | ○ | リストにあるIDだけ受け付ける（Worker側でも検証） |
| コメント | 自由入力 | ○ | 400文字 |
| 写真 | 1枚 | 任意 | JPEG。送信前にブラウザで長辺1600pxへ縮小・再エンコード（＝EXIFの位置情報が消える）。Worker側で3MB上限と画像形式を検証 |
| 釣れた魚 | プルダウン | 任意 | 固定リスト＋「釣れなかった」 |
| いつの情報か | 今日／昨日／日付 | 任意 | 初期値は今日。未来の日付と31日より前は拒否 |
| 風の体感 | 3択 | 任意 | 予報より弱い／予報どおり／予報より強い。瀬戸内側の暫定しきい値（safety.js の setouchi）の裏取りに使う |

フォームの下に注意書きを出す：他人の顔・車のナンバーが写った写真は載せない／釣り禁止・立入禁止の場所の情報は削除する／写真の位置情報は自動で消える／削除依頼の連絡先（InstagramのDM）。

## 3. 荒らし対策

- **Turnstile**：フォームにウィジェットを置き、Workerがトークンを検証。検証に失敗した投稿は保存しない。
- **連続投稿の制限**：IPをハッシュ化した値ごとに 1時間3件・1日10件。生のIPは保存しない。
- **通報**：各投稿に通報ボタン。同じ人（IPハッシュ）からの重複通報は1件と数える。**3件で自動非表示**にしてDiscordへ通知。
- **Discord通知**：新しい投稿ごとに、内容・写真・使い捨ての削除リンクを送る（既存のwebhookの仕組みを踏襲）。通知の失敗は投稿の成否に影響させない。
- 表示するときは、名前・コメントを必ずHTMLエスケープする。

## 4. 管理ページ

- Workerが `/admin` を配信。合言葉（Workerのsecret。ダディが決め、Cloudflareの画面で設定。クロロは中身を見ない）を入れると、署名付きCookie（7日）を発行。
- 一覧には非表示の投稿も出す。各投稿に「削除」（KVとR2の両方から消す）と「再表示」。
- 合言葉の試行は回数制限をかける。管理ページは検索に載せない（noindex）。
- Discordの削除リンクは投稿ごとの署名付きトークンで、開くと確認画面→削除。

## 5. Workerの経路

| 経路 | 役割 |
|---|---|
| `GET /posts?area=<id>&limit=<n>` | 公開中の投稿を新しい順に返す（CORSは釣りサイトのoriginだけ許可。短時間キャッシュ） |
| `POST /posts` | 投稿（multipart。Turnstile検証→入力検証→制限確認→保存→通知） |
| `GET /photo/<id>` | 写真の配信（長めのキャッシュ） |
| `POST /posts/<id>/report` | 通報 |
| `GET /admin`・`POST /admin/login`・`POST /admin/posts/<id>/delete`・`POST /admin/posts/<id>/restore` | 管理 |
| `GET /admin/delete?token=…` | Discordの削除リンク（確認画面→削除） |

## 6. サイト側の表示

- **現地の声ページ**：新しい順のカード一覧（写真・名前・場所・魚・いつ・風の体感・コメント・通報）。エリアで絞り込み。上部に投稿フォームへの導線。
- **SEAページ**：選択中エリアの海況の下に最新2件と「もっと見る」。0件のエリアには枠を出さない。取得に失敗しても海況の表示には影響させない。
- **検索対策**：`reports.html` の本体に、ページの説明文・投稿の注意書き・釣り場リストを静的に書く（投稿の読み込みに失敗しても中身のあるページにする。2026-09-14のソフト404の教訓）。sitemap.xml に追加。
- ヘッダーのナビに「REPORTS」を追加。

## 7. 釣り場リスト

- `src/js/data/spot-list.js` を、サイトとWorkerの両方が直接importする（コピーは作らない。リストを変えたら両方を出し直す）。IDは変えない前提で付け、追加は末尾に足す。
- クロロが5エリアの漁港・堤防・有名ポイントを下調べ→釣り禁止・立入禁止は除外、判断に迷う場所は「要確認」→**ダディがOKを出した場所だけ載せる**。
- 各エリアに「〇〇市内（詳しい場所は非公開）」、全体に「場所不明」を用意。

## 8. テストと公開

- Workerは、Instagram連携のWorkerと同じ形の手元テスト（KV・R2・Turnstile・Discordを差し替えて、経路ごとに確認）。
- サイトは手元でビルドし、フォーム→表示→通報→非表示→管理ページで削除、を通しで確認。写真のEXIFが消えていることをバイト列で確認。
- 本番への公開（Workerのデプロイ、Turnstile・R2・secretの初期設定）はダディの操作。クロロは手順を案内し、公開後の動作確認を行う。
- 公開後、Search Consoleで reports.html のライブテスト→登録リクエスト。数日はセキュリティの問題の画面も確認する。

## やらないこと（今回は入れない）
